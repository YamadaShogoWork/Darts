# ダーツ練習記録アプリ 仕様書(Android)

最終更新: 2026-11-26

## 概要

毎日のクリケット練習の結果を数十秒で記録し、苦手ナンバーと上達をグラフで確認できる、Android向けの個人用ダーツ練習記録アプリ。

元になる練習法は、YouTubeチャンネル「菊地山口の動画チャンネル」の「菊地山口練習法」(2週間でレーティングが4から8になったとされる練習法)。クリケットの 20・19・18・17・16・15・ブル を対象に、各ナンバーを埋めるのに何本必要だったかを記録し続け、合計本数の変化で上達を数値化する。苦手ナンバーを把握して克服することが目的。

- 対象ユーザー: 作者本人(個人利用)。Google Play公開は想定しない
- 開発方法: Claude CodeでAndroidアプリ(Kotlin + Jetpack Compose)として実装する。友達向けのWeb版は別に、後で作る
- 対象端末: Pixel 8
- 保存先: 普段のデータは端末内のDB(Room)。バックアップは、設定画面のボタンでJSONファイルを書き出し・読み込みする(機種変更や万一のときに使う)。ログインやクラウド同期は持たない

## 練習ルールと記録ルール

1回の練習は、20→19→18→17→16→15→ブルの順に各ナンバーを10マーク埋めるまで投げ、ブルが完了した時点で終了する。

### 練習ルール

- 対象と順番は固定で、20・19・18・17・16・15・ブルの順に進む
- マークはシングル=1、ダブル=2、トリプル=3。ブルはシングルブル=1、ダブルブル=2
- 累計が10マークに届いたナンバーは完了。完了したダートの超過マークは切り捨てる(例: 9マークの状態でトリプルなら10マークで完了)
- ターンの途中で完了した場合、そのターンの残りのダートは次のナンバーに投げる
- ブルが完了したら練習は終了。最後のターンは3投未満でもよい
- 本数は、そのナンバーに実際に投げたダートの数。ミスも数える

### 記録ルール

- 記録は1投ごとにマーク数を入力する(0〜3、ブルは0〜2)。3投で1ターンとして区切って表示する
- 1ターンの最大は9マーク(ブルは6マーク)
- ナンバーの完了とナンバーの切り替えはアプリが自動で判定する
- 入力ミスに備えて、直前の1投を取り消せる
- 1回の練習の合計本数 = 全ナンバーに投げた本数の合計。理論上の最小は29本(20〜15は各4本、ブルは5本)

## データモデル(Room)

保存するのは「メニュー」「練習セッション」「1投ごとの記録」の3つ。ナンバー別の本数や日ごとの平均は、1投ごとの記録から集計して求める。

### Session(1回の練習)

| 項目 | 型 | 内容 |
| --- | --- | --- |
| id | Long | 主キー |
| menuId | Long | Menuへの参照 |
| startedAt | 日時 | 練習開始日時。日ごとの集計はこの日付で行う |
| finished | Boolean | ブル完了まで記録したか |
| memo | 文字列 | ひとことメモ(任意) |

### DartThrow(1投)

| 項目 | 型 | 内容 |
| --- | --- | --- |
| id | Long | 主キー |
| sessionId | Long | Sessionへの参照 |
| seq | Int | 練習内の通し番号(1から) |
| target | 文字列 | 20 / 19 / 18 / 17 / 16 / 15 / BULL(メニューごとのターゲットを入れられる) |
| rawMarks | Int | 入力されたマーク数(0〜3、ブルは0〜2) |
| marks | Int | 実際に加算したマーク数(超過分を切り捨てた値) |

- ターン番号は `(seq - 1) / 3 + 1` で求める。保存はしない
- ナンバー別本数 = そのsessionIdとtargetのDartThrow件数
- 合計本数 = そのsessionIdのDartThrow件数
- 日ごとの平均 = 同じ日のSessionの合計本数の平均

### Menu(練習メニュー)

| 項目 | 型 | 内容 |
| --- | --- | --- |
| id | Long | 主キー |
| name | 文字列 | メニュー名 |
| ruleType | 文字列 | ルールの種類。最初は「クリケット10マーク」の1件だけ |

- ルール判定は画面から分けて、`PracticeRule` のようなインターフェースにする。1投を受け取り、現在のターゲット・累計・完了を返す形。メニューを足すときはこの実装を足すだけで済む

### バックアップファイル(JSON)

- 形式は1つのJSONファイル(`darts-data.json`)で、全履歴を入れる
- 普段のデータは端末内のDB(Room)に保存し、JSONはバックアップ用
- 設定画面に「バックアップを書き出す」「バックアップを読み込む」ボタンを置く。書き出しはファイル保存画面で、読み込みはファイル選択画面で、ユーザーが場所とファイルを指定する(Storage Access Framework)
- 読み込みは、機種変更やデータが消えたときに使う。端末内のDBを置き換えるため、実行前に確認を出す
- 前回のバックアップ日を設定画面に表示して、長く空いたときに気づけるようにする
- Android 11以降は、ダウンロードなどのフォルダ直下には保存できない場合がある。専用のサブフォルダを作って保存する

JSONの例:

```json
{
  "version": 1,
  "menus": [
    { "id": 1, "name": "クリケット10マーク", "ruleType": "cricket10" }
  ],
  "sessions": [
    {
      "id": 1,
      "menuId": 1,
      "startedAt": "2026-11-26T19:42:00+09:00",
      "finished": true,
      "memo": "",
      "throws": [
        { "seq": 1, "target": "20", "rawMarks": 3, "marks": 3 },
        { "seq": 2, "target": "20", "rawMarks": 1, "marks": 1 }
      ]
    }
  ]
}
```

## 画面仕様

画面は5つと、ホーム右上の歯車から開く設定画面(バックアップの書き出し・読み込み)。メインのグラフは日ごとの平均で、日別の詳細は別画面で見る。見た目は、公開済みのモックアップを基準にする: https://claude.ai/artifact/9woG88DWPmruoHZjwhcB11

| 画面 | 内容 |
| --- | --- |
| ホーム | 「練習開始」ボタン、今日の平均本数とMPR、自己ベストとそのMPR、直近の日ごとの平均、メイングラフへの入口 |
| 記録入力 | 現在のナンバー、累計マーク(○/10)、今のターンの何投目か、入力ボタン(ミス / 1 / 2 / 3。ブルは ミス / 1 / 2)、直前の1投の取り消し |
| 結果 | 合計本数、MPR、ナンバー別本数、メモ入力、保存 |
| グラフ(メイン) | 日ごとの平均合計本数の折れ線と7日移動平均。「本数 / MPR」で指標を切り替え。期間は7日・30日・全期間で切り替え。日をタップすると日別詳細へ移る |
| 日別詳細 | その日の練習一覧と各練習のMPR、各練習のナンバー別本数、ターンごとの内訳、メモ |
| 設定 | バックアップの書き出し・読み込み、前回のバックアップ日 |

### 記録入力の動き

- 1投ごとにボタンを1回タップする。ナンバー完了時は自動で次のナンバーに切り替わり、ターンの残りのダートがそのまま次のナンバーの記録になる
- ブルが完了したら結果画面へ進む
- 練習の途中でアプリを閉じても、記録済みの投は残る(未完了のSessionとして保存し、再開できる)
- 片手で押せるように、入力ボタンは画面下部に大きく置く

## グラフと指標

メインの指標は「日ごとの平均合計本数」で、少ないほど上達。

- メイングラフ: 横軸が日付、縦軸がその日の合計本数の平均の折れ線。練習していない日は点を打たず、前後を結ぶ
- 7日移動平均: メイングラフに重ねて表示する第2の線
- ナンバー別の平均本数: 直近7日・30日の棒グラフ。苦手ナンバー(本数が多いナンバー)を見つける用。日別詳細かグラフ画面の下部に置く
- 自己ベスト: 合計本数の最小値。ホームに表示する
- MPR(Marks Per Round、1ターンあたりの平均マーク数): 練習1回ごとに `合計マーク数 ÷ 投げた本数 × 3` で求める。このメニューの合計マーク数は7ナンバー×10マークで70固定なので、`70 ÷ 本数 × 3` になる(49本 → 4.29、29本 → 7.24が上限)。本数が少ないほどMPRは高く、小数第2位まで表示する。日ごと・期間の値は、その日(期間)の練習のMPRの平均ではなく、平均本数から同じ式で求める。メニューごとに合計マーク数が違う場合は、ルール側(`PracticeRule`)から合計マーク数を受け取る
- MPRは参考値。DARTSLIVEのレーティングとは別物で、レーティングへの換算は行わない

これらはすべてDartThrowの件数をSQLで集計して求める。集計結果は保存しない。

## 技術構成と開発手順

Android専用のネイティブアプリとして作る。

- 言語とUI: Kotlin + Jetpack Compose
- 端末内DB: Room、画面の状態管理はViewModel
- バックアップの書き出し・読み込み: Storage Access Framework(ファイル保存画面とファイル選択画面)。JSONの変換はkotlinx.serialization
- グラフ: Vico

### 開発の順番

1. プロジェクトを作り、下部ナビと画面の骨組み(5画面)を用意する。配色はモックアップに合わせる
2. ルール判定(PracticeRule)を作り、単体テストを書く。確認するのは、10マークで完了すること、超過分の切り捨て、ブルは最大2マーク、ターンの数え方、直前の1投の取り消し
3. 記録入力画面とRoomへの保存を作る
4. 結果画面、履歴、日別詳細を作る
5. グラフ(日ごとの平均、7日移動平均、ナンバー別の平均)を作る
6. 設定画面とバックアップ(JSONの書き出し・読み込み、読み込み前の確認、前回バックアップ日の表示)を作る
7. ダミーのメニューを足して、他メニューを足せることを確かめる

### ルール判定のテスト例

- 20に対して 3,3,3,1 と入力 → 4投目で10マーク完了、次は19
- 9マークの状態で3を入力 → rawMarks=3、marks=1、10マークで完了
- 1ターンの1投目で20が完了 → 2投目と3投目は19の記録になる
- ブルは3を入力できない(0〜2のみ)
- ブルが完了 → Sessionのfinishedがtrueになり、練習終了
- 取り消し → 直前の1投が消え、累計・現在のナンバー・ターンが元に戻る(ナンバーの完了も戻る)

## 未決事項と見送り

- バックアップは手動のボタン操作。練習のたびに自動で書き出す機能は、必要になったら後で足す
- 練習の途中でアプリを閉じたときは、未完了の練習として保存し、再開できる形を仮の決めにしている
- 完了したターンの本数は、実際に投げたダートの数で数える
- CSVの同時出力、DARTSLIVEレーティングの手入力、カレンダー、連続日数、通知は、MVPでは作らず後回し
- 音声入力は見送り。録音を始めるたびにタップが必要で、ボタン入力と手間がほとんど変わらないため
- DARTSLIVE Homeとの記録連携は見送り。公式のAPIやデータ書き出しの案内が見つからなかったため
- 友達向けのWeb版(iPhone対応)は、このアプリとは別に、後で作る。バックアップのファイル形式(JSON)を同じにしておけば、データを相互に移せる
